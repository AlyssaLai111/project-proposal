# Project Proposal

## Hotel Planner

### What and why?

Hotel Planner would be a web application for a user to keep track of the prices, ratings, and accessibility of multiple hotels they are considering and help them find the best location among them. 

If you've ever had to plan a vacation and book hotels, you've probably had several tabs open at once of hotels on different websites. You'd have to constantly switch between tabs, analyze prices, read reviews and ratings, and check amenities and accessibility for each one to find the best fit for your travels. Hotel Planner would help keep things in one place and allow you to compare and contrast your options clearly. 

### For whom?

Anyone who wants to go on vacation, has to book a hotel, and is struggling to choose from a few options. 

### How?

The user will be able to create a "new project" that represents their vacation, and in it, they can add "cards" of hotels, inputting information such as prices and ratings (and optionally amenities, accessibilities, and personal notes) that will be displayed on the card in a clear manner (i.e. readable style that highlights the important bits) and be edited at any time. 

From there, they can prioritize certain details, like cheaper prices over better ratings or better ratings for cheaper prices, using a slider, and then Hotel Planner calculates a score based on the weights given to each aspect to show the user their best options. 

### Scope

For a group of 4-6 programmers, the project shouldn't be too easy to do in a semester because it has to account for the several possible details of a hotel that a user may want to add, and there has to be a way to quantify those details to be able to calculate a "best fit" score. It also wouldn't be too ambitious because everything is limited to given information from the user, so the project doesn't have to do any sort of webscraping.
